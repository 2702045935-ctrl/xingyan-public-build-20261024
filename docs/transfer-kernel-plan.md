# 星言传输内核重构

## 目标

图片、视频、语音和普通文件统一走一个可恢复、可观测、可扩展的传输内核。
不为微信做视觉仿制，只以可靠性、速度和弱网体验作为工程基准。

## 架构边界

### 客户端

- `TransferJob` 持久化任务：远端文件 ID、分片大小、已完成分片、哈希、
  重试次数、进度和最终媒体 URL。
- 每个分片独立重试；网络切换后从服务端确认的 offset 继续。
- 大文件从本地 URL 流式读取，不把整份文件放进内存。
- 上传完成立即返回媒体 ID；转码作为异步处理状态，不阻塞消息发送。
- 图片先本地压缩，视频先本地导出安全规格，文件不自动改变内容。

### 服务端

- `POST /api/transfer/init`：声明大小、MIME、文件名和内容哈希。
- `POST /api/transfer/:id/chunk`：幂等分片写入。公网反代统一允许大请求 POST。
- `POST /api/transfer/:id/complete`：校验分片和总哈希，返回媒体对象。
- `GET /api/transfer/:id`：返回上传、扫描、转码、可播放状态。
- 后端采用可替换存储适配器：本地磁盘优先，后续接对象存储。
- 正在接收的数据直接流式加密，不再“先明文落盘再整文件重写”。
- 视频转码进入异步任务队列，使用幂等任务 ID 和失败重试。

### 分发

- 图片、文件与已完成的 MP4/HLS 通过签名 URL 访问。
- 后续把签名上传和播放地址接到对象存储/CDN，应用服务器只保存元数据。

## 分阶段

1. 分片协议、任务持久化、断点续传、流式加密、本地存储适配器。
2. 异步媒体任务、转码状态、消息先发后处理、失败恢复。
3. 对象存储/CDN 适配、并发限流、后台续传和跨网络恢复。

## 验收

- 5MB、20MB、60MB 文件都有稳定进度和断点续传。
- 上传中断后不重复发送已完成分片。
- 服务端内存占用不随文件大小线性增长。
- 短视频上传完成后消息立即可见，转码状态异步更新。
- 弱网切换、后台中断、重连后可恢复。
- 上传耗时、首字节时间、失败率和恢复成功率都有自动测试记录。

## 原则

- 不回退到 base64 上传。
- 不在请求内等待整段视频转码。
- 不把完整的传输状态塞进聊天消息或全局 SwiftUI 状态。
- 不复制微信界面和代码。
