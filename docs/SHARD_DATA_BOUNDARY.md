# 分片数据边界

## 当前模式

正式 7 片当前共用一个数据目录：

`/opt/xingyan-mainline/data`

这是兼容期共享模式，不表示物理分片已经完成。多个进程共享同一目录时，任何新增写路径都必须先声明归属，不能默认所有分片都可写。

## 数据分类

| 分类 | 代表数据 | 目标归属 |
| --- | --- | --- |
| `user-shard` | 用户资料、好友关系、设备资料 | 按 `userId` 唯一分片 |
| `chat-shard` | 会话、已读、投递、消息 JSONL | 按 `chatId` 唯一分片 |
| `moment-shard` | 朋友圈、评论、点赞、通知 | 按动态或作者 key 唯一分片 |
| `payment-authority` | 支付账本、转账、红包、支付意图 | 固定支付权威，不能随社交哈希漂移 |
| `object-store` | 上传图片、视频、文件、转码对象 | 独立对象存储 |
| `global-replicated` | 品牌、配置、音乐、游戏目录 | 只读或单写者广播 |
| `global-log` | 审计、监控、推送日志 | 独立日志系统 |
| `derived-rebuild` | 缓存、影子分片、旧迁移目录 | 可从权威数据重建 |
| `archive` | 历史备份、临时副本 | 不参与线上读写 |
| `secret-authority` | 密钥文件 | 安全存储，禁止复制到普通分片 |

## 写规则

1. 一个数据对象只能有一个权威分片。
2. 其他分片只能转发命令，不能直接改写同一对象。
3. 缓存、快照、影子副本必须标记为 `derived-rebuild`。
4. 支付事实不跟随社交哈希迁移。
5. 归档文件不参与线上路由。
6. 密钥文件不进入普通分片存储。
7. 新文件类型必须先加入分类器，否则发布门禁失败。

## 迁移顺序

不能一次把整个共享目录切开。按域迁移：

1. 只读清单和哈希
2. 用户域
3. 会话与消息域
4. 朋友圈域
5. 媒体对象
6. 支付权威单独迁移
7. 最后处理全局配置和日志

每一步都必须支持旧路径回滚，并在切换前完成数量、序列、哈希和最后修改时间对账。
