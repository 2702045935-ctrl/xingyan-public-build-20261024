# 双 Cell 影子接入规则

## 当前判断

当前生产是单业务机上的 7 个逻辑分片，仍是共享数据目录。
离线物理副本、物理目录验收和只读对账能力已经完成，但不能称为双 Cell。

同机不同目录、同机两套进程、同机两个端口都不是双 Cell。

## 双 Cell 最低条件

1. Cell A 和 Cell B 使用不同物理主机。
2. Cell A 和 Cell B 的数据根目录不能相同，也不能互相包含。
3. 两个 Cell 属于不同故障域。
4. Cell B 只接受影子读取，不镜像任何写请求。
5. 两个 Cell 使用完全相同的冻结路由计划哈希。
6. 影子采样率不能超过 10%，并有独立 QPS 上限。
7. 每个请求设置独立超时，Cell B 超时不能阻塞 Cell A 的响应。
8. 比较前只允许忽略明确列出的非业务字段，例如时间戳和请求 ID。
9. 至少积累规定数量的样本，并对差异生成稳定报告。
10. Cell B 故障时自动退化为不采样，不影响 Cell A。

## 计划校验

复制 `docs/DUAL_CELL_SHADOW_PLAN.template.json`，填写真实的 Cell A / Cell B 信息：

```text
node server/tools/dual-cell-contract.js \
  --plan=<双 Cell 计划> \
  --out=<契约验收报告>
```

出现以下任一情况直接拒绝：

- 主机相同。
- 数据根目录重叠。
- 故障域相同。
- `mode` 不是 `shadow`。
- `writeMode` 不是 `disabled`。
- `readOnly` 不是 `true`。
- `writeMirror` 不是 `false`。
- 采样率超过 `0.1`。
- 路由计划哈希不一致或格式错误。
- 比较超时、QPS 或必需样本数不在允许范围。

## 下一步顺序

1. 通过契约验收。
2. Cell B 部署与 Cell A 相同路由计划的只读物理副本。
3. 在 Cell B 上启动独立只读服务。
4. 只镜像 GET/读取请求，不镜像发送、支付、好友、群操作等任何写请求。
5. 从低采样率开始，持续比较用户、会话、消息、朋友圈和游标响应。
6. 差异为零且样本量达标后，才讨论故障切换。

契约通过不等于可以切流。切流还必须单独通过容量、延迟、故障和回滚演练。
